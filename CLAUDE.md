- We are building a library used by other developers. Please provide a documentation for every function and class you create.
- You are forbidden to commit. Never run `git commit` (or any command that creates a commit, such as `git commit --amend`), and never push. Leave all changes in the working tree and tell the user what is ready to be committed — committing is the user's decision alone, even if they ask for a "version bump" or the work looks finished.
- Releases are published to npm by CI (`.github/workflows/publish.yml`): every push to `main` that changes `version` in `package.json` is built, tested, published and tagged. Never run `npm publish` yourself.
- At the end of every task that changes the published SDK (anything under `src/`), suggest a version bump: name the level (`patch` for fixes, `minor` for new backwards-compatible API, `major` for breaking changes), the resulting version, and why. Only bump when the user asks, and then with `npm version <level> --no-git-tag-version` (plain `npm version` creates a commit and a tag, which is forbidden above).
